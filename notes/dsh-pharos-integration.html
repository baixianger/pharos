DeepSeek Harness 接入 Pharos

如何把 dsh（DeepSeek Harness）作为第三种 coding agent 接进 Pharos——已核实两端接口，给出三个方案与分阶段路线。

TL;DR

dsh 走 API 双向桥：Pharos 持有 dsh web，入站用 session.prompt/session.append 推消息（含 @），出站读 session.events/history 把回复镜像回房间——零 hook、零 send-keys；pharos skill 只留给 agent 主动动作。

02

三个方案

A. 第三种 AgentKind

加 .dsh，复用现有启动 / 跨主机 / CLI 管线。

推荐起点低风险~2 天

Trade-offs
  • + 一致 UX，复用 launch / cross-host / issue-start 全链路
  • + dsh 侧零改动，凭 ~/.dsh 自配置（密钥/模型）
  • − headless 无 resume；交互面是浏览器不是终端
  • − 会话日志是 zstd，发现/恢复要额外解码
B. dsh 原生 skill

投一个 pharos skill，让 dsh agent 以工具调用 pharos CLI。

低风险~1 天

Trade-offs
  • + 绕开「无 shell hooks」，和 Claude/Codex 同走「CLI 驱动 Pharos」路径
  • + 一条 SKILL.md 即可，pharos mesh recv/send + issue 命令
  • − 手动 recv（无 Stop 钩子自动投递）
  • − 每台机器需装一次
C. HTTP API 驱动

Pharos 常驻 dsh web --port N，走 /api 会话/注入。

中风险spike

Trade-offs
  • + 干净会话列表/恢复（session.list/create/prompt）
  • + 程序化 @mention 注入，等价于 hooks
  • − 需常驻 web profile + 端口/状态管理
  • − rc 预发布，API 会变

顺序推进：A → B → C。A 是地基（先把 dsh 当普通 agent 用起来），B 最快补齐 mesh，C 是达到 Claude/Codex 同等的深度。

tmux send-keys 键入复活不可用确定高改走 session.prompt；或 DSH 侧补 TUI profile
cwd 归一化有损低低以 session.query/API 为准（P3）

07

唤醒 / 复活机制

Pharos 唤醒 idle agent 靠三件事：hooks 投递、tmux send-keys 键入、sweep 轮询再 poke。dsh 现状对照如下。

Pharos 机制前提dsh 现状
Stop / PostToolUse hook 投递agent 原生 shell hooks无 shell 层 hooks；但有进程内 Cordis 事件，插件可 ctx.on 订阅（§08）
tmux send-keys 键入复活终端交互 TUI 会读键盘无 TUI：web（浏览器）+ headless（一次性，argv 读任务、不读 stdin）
sweep 轮询 roster 再 poke上两者可用换成 HTTP API session.prompt 注入

出站（回消息）三种方式，自动程度递增：

出站机制适用
③ 读 transcript 镜像（推荐）Pharos 经 API 读 session.events/session.history（或订阅其 named-stream），把 assistant 消息自动投回房间基础「人→agent→回房间」，agent 无需知道 Pharos
② 不装 skill、靠推断agent 用 bash 跑 pharos help 自己摸索 CLI偶发；不可靠（flag 易错）
① pharos skillagent 显式调 pharos mesh send / update addagent 主动动作：@别人、写日志、开 issue

结论：send-keys 键入这条对 dsh 不成立，而且也不需要——入站 session.prompt（发+触发回合）/ session.append（追加消息，语义需 spike 确认），出站读 transcript 镜像，零 hook、零 TUI。skill 只留给 agent 主动的 Pharos 语义动作；要保留 send-keys 才需给 dsh 写终端 TUI profile（DSH 侧工作）。

08

官方插件规范（Cordis）

dsh 有正式插件规范：底层是 DeepSeek 的 cordis TS 插件框架，叠加 dsh 自己的扩展点。插件是命名导出 name/inject/apply 的 ESM 模块。

扩展点API给 Pharos 的用途
工具ctx.tools.register(defineTool({ name, description, parameters, output, execute }))一组 pharos_* 原生工具
事件 / hookctx.on('agent/pre-step' | 'session/event' | 'tools/result', …)@mention 自动投递（进程内等价 Stop hook）
提示词system-prompt/assemble / ctx.systemPrompt.tools()注入用法说明
MCP一插件接一 server → ctx.tools.register()若 Pharos 未来暴露 MCP server
装载profile bundles + - id / name / inject / config 行 + dsh plugin add <pkg>装进 web / headless profile

推荐 @baixianger/dsh-plugin-pharos：注册 pharos_mesh_send / pharos_mesh_recv / pharos_issue_add / pharos_update_add / pharos_list，execute 里 shell 到 pharos CLI（内嵌绝对路径，与 hooks 一致）。比 skill 强：确定性 schema、自动进工具目录、不靠模型推断；可再叠加一个事件监听做自动 @mention 投递（需 spike 选事件 + agent.inject()）。
