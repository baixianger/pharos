### 清单故障期间保留已打开 Session（2026-11-07）

桌面服务此前在远程 ACP 清单查询失败时移除该主机 DSH 服务及 Session 绑定，即使已打开 Session 和事件订阅仍在使用。现在同一主机与 SSH 目标的清单失败只记录错误，保留已有服务、最后成功清单和绑定，Session 状态为 unknown，标记 `inventoryStale`；桌面 Session 行及 Project 的 Session 行显示 `Inventory unavailable · last known`。成功刷新使用新清单替换缓存并移除过期标记；成功返回空清单会移除旧绑定，SSH 目标变更或主机移除不会沿用旧绑定。若同次远程 checkout 映射读取失败，Project 关联仍按现有规则变为未知，不拿旧路径冒充当前数据。

隔离桌面服务测试用模拟 DSH Host 验证：故障前后通过同一服务读取、成功恢复后仍复用 Host、成功空清单移除旧绑定、目标变更后不复用；程序驱动 WKWebView 检查 Session 和 Project 行的过期标记。两项通过，见 `internal/evidence/2026-11-07_dsh-inventory-stale-ui-final.log`。另用 mac-air 保留的真实测试 Session 尝试同一流程，首次远程历史读取即失败，尚未进入模拟清单失败步骤；重试仍失败，见 `internal/evidence/2026-11-07_dsh-inventory-retention-real-phase.log` 和 `...-real-retry.log`。因此真实远程服务故障前后不中断尚未验收，SSH 关闭根因和远程 Project 跳转仍待查。

### 同一 SSH 连接建立 Host 和转发（2026-11-07）

只读受控对照显示：mac-air 上保持一条独立 SSH 会话时，第二条独立 SSH 会话以 255 退出且 stderr 脱敏分类为 connection closed；在第一条连接上通过 SSH ControlMaster 请求动态转发则成功，监听端口可连接。见 `internal/evidence/2026-11-07_remote-ssh-concurrency-control.log`。这是本机与该远端的实测现象，不足以确定远端策略或 SSH 实现的根因。

远程 `DshWebHost` 现为它自己启动的 SSH Host 建立独立、权限 0700 的临时 ControlMaster 目录；收到 Host 端口后，通过该连接添加本地转发，避免另起一条持久 SSH 连接。结束时关闭 Host 输入、等待退出并清理自有控制目录；不修改用户 SSH 配置或清理归属不明的进程。真实 mac-air 测试中，先建立交互订阅再读取保留 Session 的 71 条历史通过（`internal/evidence/2026-11-07_dsh-shared-ssh-interactions.log`）；桌面服务在模拟一次清单故障前后均读到四个完成回合且缓存标记为过期（`...dsh-inventory-retention-shared-ssh.log`）；正常释放后测试启动的一个 SSH 子进程退出（`...dsh-shared-ssh-lifecycle.log`）。模拟故障不是真实断网或真实 SSH 清单失败，异常退出和并发多窗口仍未验证。

该改动只合并一个 DSH Host 自身的 Host 和转发连接；桌面服务的远程 Codex、ACP 清单、checkout 查询及其他 Host 仍可各自创建连接。完整远程 DSH Project 探针仍因服务内 ACP 初始化时 SSH 255 而 skipped，尽管独立查询同一远端返回 185 条，见 `internal/evidence/2026-11-07_remote-project-dsh-shared-ssh.log`。需要协调跨服务连接及其所有权后重新验证完整 Project 流程；不能将本次真实单 Session 测试称为全链路通过。

### 跨服务共享 SSH 与远程 Project 闭环（2026-11-07）

桌面为每个配置主机创建私有 SSH ControlMaster：Codex 转发、DSH ACP 清单、DSH Web Host、Antigravity ACP 和远程 Project 路径查询共享该连接；本机私有控制目录权限 0700，目标变化或服务释放时关闭。普通 SSH 默认在控制 socket 不可用时可能新建连接；本实现的子命令使用失败的本地 ProxyCommand 防止静默回退独立连接，参考 [OpenSSH ssh_config](https://man.openbsd.org/ssh_config)。保持父进程写入管道，正常关闭时关闭输入并设超时终止，测试进程退出后确认未遗留本次主连接。曾有一次测试异常结束后产生可确认归属的 SSH 主连接，已只终止该测试进程；其他归属不明的 SSH 进程未处理。强制终止、连接中断重建和跨窗口竞争尚未系统验证。

真实 mac-air 对照：同一共享连接上的 Codex 列表返回 7 项、DSH ACP 返回 185 项、远程 Project 路径返回 78 项，DSH Host 同时读取保留 Session 71 条记录；并发命令、转发和取消、关闭后的失效参数不能创建独立连接通过，见 `internal/evidence/2026-11-07_shared-ssh-real-failclosed-final.log`。远程 DSH 历史与实时 follow 都把初始快照限制为一条消息；历史仍通过 HTTP 分页，follow 的快照处理仍重新读取完整历史进行补齐。真实桌面测试从 Project 打开匹配的远程 DSH Session 并渲染历史通过（`internal/evidence/2026-11-07_shared-ssh-desktop-dsh-project-passed.log`）；共享连接下 Codex Project 同样通过（`...shared-ssh-desktop-codex-project.log`）。另有两次 UI 测试在 `NSApplication.shared` 附近遇到 `DecodingError`，重试后通过，原因未知。

这证明 mac-air 上各一个远程 DSH 和 Codex Project 跳转、程序驱动 WebKit；不代表所有 Session、真实远程 Antigravity、物理鼠标、网络断连重连或强制退出均已验收。测试不发送模型提示。四项本地服务、事件回放与 UI 回归通过，见 `internal/evidence/2026-11-07_shared-ssh-regression.log`。

### 共享连接关闭后的桌面刷新（2026-11-07）

桌面清单刷新现在发现已有共享 SSH 连接已关闭时，不受通常 60 秒刷新间隔限制；并发刷新仍被抑制。替换同一目标的连接前，后台等待此前由应用持有的 SSH 子进程退出，最多等待五秒；超时明确报告失败，避免旧连接仍占用远端时立即建立新连接。该检查只对本地已知进程关闭生效，不等于能即时探测所有网络分区。

使用 mac-air 保留的 DSH 测试 Session，先通过真实桌面服务读取四个回合，主动关闭该测试持有的共享连接，再立即触发桌面清单刷新；修复前新连接未能建立（`internal/evidence/2026-11-07_dsh-desktop-shared-ssh-reconnect-before.log`），等待旧子进程退出后，新连接、实时清单和相同四个历史回合均恢复（`...dsh-desktop-shared-ssh-reconnect-after.log`）。独立真实 Host 对照中两次连接各读取 71 条记录（`...dsh-shared-ssh-replacement-real.log`）。四项刷新条件、清单保留、事件回放和非法 SSH 目标回归通过（`...dsh-desktop-shared-ssh-reconnect-regression.log`）。这是主动关闭自有连接的受控测试，不是物理断网、未应答连接或进行中模型回合的恢复验收。

### 已打开 Session 的连接替换（2026-11-08）

桌面共享连接替换时原 DSH 服务被重建；仅刷新清单不会改变当前选中的 Session ID，原视图模型过去不会自动重载。现在同目标连接恢复、DSH 清单成功且原 Session 仍在清单中时，桌面发布带精确 Session ID 的 `sessionConnectionRestored` 事件；对应视图模型合并等待当前加载后重读历史、Goal/Todo 与审批快照，并通过新服务重新建立 follow。一次重连或清单失败后的待恢复 ID 保留到成功刷新，SSH 目标改变时清除，不向其他 Session 发送恢复事件。历史显示已完成回合时清除旧的进行中状态；加载期间到来的新回合状态使用修订号保护，成功重载只清除加载期间未被更新的旧错误。

DSH Session 输入区的加号可选择最多五个、合计 10 MB 的文件；普通文件通过对应 Host 和精确 Session 暂存并随文本提交。文件草稿按 Session 分开，失败保留文字和文件，确认成功后仅移除本次提交的文件；命令和 steer 不接收附件。此限制是当前桌面实现的内存上限，并非 DSH 官方协议限额。其他 Agent 暂不显示该入口，底层请求会明确返回不可用。上传使用内存和 base64，未实现分片、进度、取消、暂存回收或不确定结果的幂等恢复；网络异常后不能断言服务端未接收。
