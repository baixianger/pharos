# Codex Session 协议

Peer 事件缺口现触发打开中的 Session 重载；模拟验证和真实 Codex 恢复仍待验收的边界见 [交接](../../../handoff.md)。

Peer 会话清单和 Codex 可用状态现通过同一次 Host 清单快照取得，避免不同轮次混用；适配器和验证边界见 [交接](../../../handoff.md)。旧 Host 需要升级后支持该查询。

**Peer 项目关联（2026-11-08）**：Host 按本机 Pharos 项目 UUID 提供 checkout 映射，桌面可将此 Agent 的 Peer Session 关联到对应 Host 路径；真实本机偏好与 loopback Iroh 映射一致，跨机器与真实桌面项目跳转未验收。见 [项目记录](../../../2026-11-07_project-session-routing.md)。

**真实本机 Host RPC 清单（2026-11-08）**：只读实测经生产 `HostLocalSessionService` 和 loopback Iroh 返回 1 条，清单未标不可用；不代表真实远程或 HITL / Goal / Todo 验收。测试入口见 [交接](../../../handoff.md)。

**Pharos peer 改造进度（2026-11-08）**：受控 Codex fixture 已通过 Iroh Session RPC 测试；Host 启动路径新增本机 Codex Session RPC 处理器，生产客户端尚未接入，真实 Host 和远程 Session 未验收。事件协议升为 `host.session.events.v2`：事件缓冲溢出和 Host 重启须报告缺口；请求键在 Host 执行前落盘，重启后重复键结果未知、不能自动重发，持久对账和断电安全仍未验证。详见 [交接](../../../handoff.md)。 桌面已实现显式 UUID 映射下的 Peer 优先、断线粘住原路径及 PEER / SSH 展示；mock Peer / WKWebView 测试通过，真实 IPC → Host 及真实备用未验证。

**远程架构偏差（2026-11-08）**：当前通过 SSH 转发远端 Codex App Server socket，本机直接调用厂商协议，不符合用户确认的 Pharos ↔ Pharos 主路径边界。已有远程实测仍证明旧路径的行为，不证明目标架构完成；迁移范围和验收见 [架构决策与审计](../../../RFC-006-UNIFIED-CLIENT-AND-BACKEND-INTEGRATION.md#remote-pharos-boundary-and-current-deviations)。 用户确认保留这一 SSH 直连作为明确标识的备用路径；涉及未知执行结果时不得自动重发。

mac-air 真实 Codex 命令审批已通过生产桌面显示并取消，同一回合在服务事件、历史及独立连接重读中均为 cancelled；测试没有批准命令。版本与覆盖边界见 [Codex 验证记录](../../../2026-11-07_codex-session-validation.md)。

mac-air 上一个真实 Codex Project 关联在测试自有共享 SSH 连接关闭后重新建立：清单和 checkout 映射恢复，生产 WebKit 再次从 Project 打开同一 Session 并渲染历史。不是物理断网或在途回合恢复；证据见 [Project 关联记录](../../../2026-11-07_project-session-routing.md)。

远程 mac-air 专用持久 Session 已验证 Goal 协议创建、读取、完成和清除；生产桌面从真实清单打开并观察初始、完成和清除，独立 SSH 连接重读 Goal 为空及种子历史。写入由独立协议客户端发起，未证明模型主动创建或桌面编辑 Goal。版本与证据见 [Codex 验证记录](../../../2026-11-07_codex-session-validation.md)。

Codex Session 输入的 `/goal`、`/goal <目标>`、`/goal pause`、`/goal resume`、`/goal clear` 已路由至对应 App Server Goal RPC，不再作为普通模型消息发送；写操作标记 `origin=user`。已有 Goal 时创建前拒绝覆盖，但读取与写入之间不是原子操作。真实远程桌面已验证创建、暂停、恢复、清除，以及查询、对已有 Goal 的拒绝和草稿保留；测试目标限制使用工具和文件，独立连接重读目标为空且无在运行回合。真实断网和多客户端并发仍未验收。本机另一次真实多步骤回合产生命令执行但未发结构化 Plan，具体探针和限制见上述验证记录，不视为 Todo 通过。

2026-11-07：本机 CLI 0.166.0，mac-air 0.162.1。桌面复用 shared daemon Unix socket；远程经 SSH 转发同一用户的 socket，Session ID 含主机前缀。列表 `thread/list`、历史 `thread/read`、发送 `turn/start`，消费 item、turn、用量和 Goal 通知。注意 Codex 协议叫 thread 的对象在 Pharos 中对应单人 Session，不是 Mesh Thread。实现见 [服务](../../../../Sources/PharosRuntime/LivePharosClientService.swift) 和 [远程连接](../../../../Sources/PharosRuntime/Adapters/Codex/RemoteCodexTransport.swift)。

结构化问答是服务端 `item/tool/requestUserInput` 请求，以原始数字或字符串 JSON-RPC ID 回写；仅处理该连接自己发起的 turn，避免 shared daemon 广播导致旁观者抢答。`serverRequest/resolved` 表示请求结束，也可能被其他客户端回答或清除。持久 Session 使用 `thread/goal/get` 和 Goal 事件；Plan 使用 `turn/plan/updated`。ephemeral Session 的 Goal 查询不支持。

真实桌面 WebKit 问答及助手回合完成已验证；测试注入 Plan 模式，桌面当前无模式选择。真实 Goal 初始显示、完成和清除事件已在桌面显示核对，Goal 变更由测试 API 发起。两次真实 Todo/Plan 探针没有原始 Plan 事件。本机 CLI 命令审批取消和文件审批拒绝已通过程序驱动桌面 WebKit 验证；实际允许、物理鼠标、远程审批和重连未验收。版本、实验和边界见 [Codex 验证记录](../../../2026-11-07_codex-session-validation.md)。

Project 关联按主机的 checkout UUID→路径映射生效，已配置 SSH 的远程 Mac 只读获取其本地映射；不以跨主机相同路径推断，见 [Project 关联记录](../../../2026-11-07_project-session-routing.md)。

范围约束：只使用 CLI 或明确支持的 App Server 协议，不针对 Codex 桌面 GUI 实现专门接入。当前 `thread/list` 未传 `sourceKinds`，共享服务可能返回多种来源；已生成的本机协议 schema 说明可按来源过滤，但当前实现尚未区分来源，写入权和其他客户端状态不能仅由列表推断。

## 命令审批选项

本机 CLI 0.166.0 的真实只读测试回合请求执行安全的 `printf`，原始 `availableDecisions` 为 `accept`、`acceptWithExecpolicyAmendment`、`cancel`，没有 `decline`。`cancel` 表示拒绝并中断回合，与拒绝但继续的 `decline` 不同；服务仅在实际提供时显示取消回合并回写 `cancel`。真实 CLI 测试观察到请求、确认和 cancelled 回合；生产桌面 WebKit 测试也观察到真实审批卡、提交取消后卡片消失及对应历史回合 cancelled。详见 [验证记录](../../../2026-11-07_codex-session-validation.md)。

远程桌面 Codex 转发现与 DSH、ACP 清单和 Project 路径共用主机的私有 SSH 连接；mac-air Codex Project 打开 Session 并渲染历史的程序驱动 WebKit 回归通过。连接故障、生命周期及证据见 [DSH Session 文档](../../dsh/sessions/2026-11-07_protocol.md)。

## 远程共享连接恢复（2026-11-08）

桌面共享 SSH 连接替换、远程 Codex 清单成功刷新后，对仍存在且原先属于该主机的精确 Session ID 发布恢复事件；打开的 Session 视图模型自动重读历史、进度和审批。若刷新失败则保留待恢复 ID，目标主机变化或移除时丢弃旧目标的恢复关联。mac-air 的受控测试主动关闭应用持有的 SSH 连接，桌面重建连接后不手动请求历史，视图模型自动重新加载同一 Codex Session 的 12 个回合；证据 `internal/evidence/2026-11-08_codex-reconnect-autoreload-real.log`。测试是只读、程序调用视图模型；不涵盖物理断网、在途回合、审批恢复、服务端历史变化或 WKWebView 重连交互。

共同 Session 视图模型已防止历史读取期间的回合事件和新提交消息被旧快照覆盖；受控测试和远程 DSH 回归见 [DSH Session 文档](../../dsh/sessions/2026-11-07_protocol.md)。真实 Codex 网络故障期间并发事件仍未验收。

共同 Session 视图模型现以请求代次防止重叠历史请求乱序覆盖，并保持事件监听；模拟乱序回归及 mac-air 受控连接恢复通过，见 [DSH Session 文档](../../dsh/sessions/2026-11-07_protocol.md)。真实远端乱序与断网期间进行中的回合仍未验收。

## 计划按回合隔离（2026-11-08）

本机 0.166.0 的默认模式与显式 plan 模式各尝试一次诱发结构化 `turn/plan/updated`，均未观察到该事件，真实 Todo 端到端仍未通过。本机生成的 schema 明确该事件含 `threadId` 与 `turnId`；桌面服务现清除上一回合的计划，并忽略在新回合开始后到达的旧回合计划。受控通知验证了前述问题、修复和不同 Session 隔离；实验与局限详见 [Codex 验证记录](../../../2026-11-07_codex-session-validation.md)。

Plan 模式另有自由文本 `plan` item。此前生产 Session 服务会丢弃其最终文本及增量；现实时显示增量并在规范化回合中保留最终文本与原始类型。真实本机持久 Session 的完成事件及历史重读通过；该文本不等于结构化 Todo，详见 [Codex 验证记录](../../../2026-11-07_codex-session-validation.md)。

文件审批请求以 Session、turn 和 item ID 关联此前 `fileChange` 的完整变更详情，桌面审批卡可拒绝或单次允许。本机真实只读测试核对了拒绝与文件未创建；另对精确匹配的单个临时新建文件允许一次，核对实际内容及历史。多文件变更数组现在映射为独立 patch；真实多文件、远程和乱序仍未验收，详见 [Codex 验证记录](../../../2026-11-07_codex-session-validation.md)。

Codex 文件变更历史显示后端 item 状态；本机真实拒绝后 `declined` 与桌面标记已核对，避免把拒绝的拟议修改显示成已完成。

后续真实本机持久 Session 已通过程序操作生产 WKWebView 验证计划实时显示、最终内容标记与历史重读；清单和 plan 模式由测试注入，不代表普通桌面模式选择或结构化 Todo 已完成。见上述验证记录。

远程 mac-air 真实只读 ephemeral Session 的结构化问答已通过 SSH 和生产 Session 服务完成请求、答复和继续；plan 模式由测试注入。另一次远程桌面测试正常发现并打开专用 Session，但等待期间未出现问答，标记为跳过，原因尚待诊断；不能据此宣称桌面闭环通过。测试方法和证据见 [Codex 验证记录](../../../2026-11-07_codex-session-validation.md)。

后续确认 `thread/read` 并不订阅当前连接；即使 daemon 已加载 Session，也须恢复它。生产服务现对清单中发现的 Session 在首次发送前执行 `thread/resume`。真实 mac-air 桌面测试已看到结构化问答、选择与确认、回复和历史重读，plan 模式仍由测试注入；旁观实时订阅及连接重建后的恢复尚未验收。完整证据与此前跳过实验见 [Codex 验证记录](../../../2026-11-07_codex-session-validation.md)。

后续已为 UDS 连接、通知与审批引入代次：连接变化后下一次发送需重新恢复 Session，旧代次事件忽略，旧审批在查询或回答时撤回且不得写到新连接。运行中失联后再次发送须先从历史确认原回合已结束。本机真实独立客户端在完成的两个回合间替换连接成功；远程真实正常问答也回归通过。远程断网、审批进行中断线和恢复/发送之间的竞态仍未验证或解决，详见 [Codex 验证记录](../../../2026-11-07_codex-session-validation.md)。

后续已修复恢复与发送之间的代次竞态：真实本机测试在恢复后关闭测试连接，以旧代次发送被拒且历史未新增回合；正常续聊及真实远程桌面问答均回归通过。远程真实断网及发送后响应丢失仍未验收，见 [Codex 验证记录](../../../2026-11-07_codex-session-validation.md)。

连接变化导致启动前失败时，桌面现在保留普通文本草稿并显示错误；受控生产服务与 WKWebView 测试确认没有发送回合（`internal/evidence/2026-11-08_session-text-draft-desktop-live-final.log`）。发送后响应丢失时结果可能未知，不能把草稿保留当作重试安全保证。通用草稿交互见 [输入能力清单](../../../2026-11-08_session-composer-capabilities.md)。

steer 失败不再清除正在运行的原回合状态，原回合结束事件仍可正确清理；这是受控视图模型验证，真实 Codex steer 断网尚未验收。

Codex 派生 Session 的 Thread 投递现在以具体 `thread.id` 寻址，不以可能指向根的 `sessionId` 推断；本机真实派生 Session 经桌面加入 Thread 后完成回复，根 Session 没有该回复。受控共享根字段复现、实际字段边界和旧记录迁移限制见 [Codex Thread 协议](../../codex/threads/2026-11-07_protocol.md)。
