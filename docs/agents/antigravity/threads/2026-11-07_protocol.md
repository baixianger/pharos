## 共同的 Thread 通信路径（源码）

桌面 Thread 是 Pharos Mesh room，不是厂商自己的 Session 对象。`DesktopPharosClientService` 在 Broker 模式使用 `list`、`who`、`history` 和 `say`；分布式模式调用 Mesh chat 接口。成员使用不可变 member ID；界面加载 roster 时读取 member 的 `kind`、`host`、`state` 等，缺失状态为 `unknown`。文本里的 `@name` 被解析为定向目标；Broker 源码只为显式目标建立 mailbox，普通聊天不等于向所有 Agent 投递。Runtime 桥尝试用 `delivery.submit-member` 携带 member ID、消息 ID、room、sender 和幂等键；未由 Runtime 接受时，Broker 保留 mailbox 并走保守的唤醒路径。详情见 [桌面服务](../../../../Sources/Pharos/UI/Shell/DesktopPharosClientService.swift)、[Runtime 投递桥](../../../../Sources/PharosRuntime/MeshRuntimeDeliveryBridge.swift) 和 [Broker](../../../../Sources/PharosMeshCore/MeshBroker.swift)。

Thread 视图每 3 秒刷新最近 200 条历史和当前 roster；右栏显示 member 的 Mesh 状态，读取失败的成员显示 `unknown`，model/mode 留空。状态是 Broker `who` 或分布式 Mesh 已有的 presence 快照，不是厂商状态的直接证明；该视图虽处理 `memberStatusChanged`，当前生产服务没有发出该事件，因此这里是轮询而非推送。隔离真实 Broker 测试验证了 unknown → busy 自动刷新、blocked 刷新，以及 room、成员、发送和 mailbox；WKWebView 测试确认状态文本显示。各家真实 hook/driver 上报、分布式 Mesh、桌面到真实代理投递与回复仍需验收。桌面消息历史目前统一显示 `unverified_fallback`：房间落盘、Runtime 入队和 mailbox 领取本身都不证明 Agent 已处理消息；生产服务尚未将逐目标消费回执关联回来。隔离真实 Broker 测试验证了发送前后、mailbox 领取后仍保持未验证；这不等于验证了真实 Agent 收到或回复。


2026-11-07 投递边界：Swift Runtime 和 Rust Runtime 的外部插件投递要求驱动声明 `delivery.poll`、最近 15 秒内登记/心跳且会话最近 45 秒在线并未归档；否则回退 Mesh mailbox。Rust Runtime 另有内置 Codex worker：已登记的 managed Codex 会话可进入队列，不依赖插件心跳；它会等空闲、必要时恢复会话并调用 `turn/start`。Swift Runtime 没有这个内置消费者。隔离 Broker + 真实 Unix socket + Swift Runtime 的测试验证队列中的 room、正文、消息 ID；Rust 测试覆盖无领取能力、离线、过期与正常接收。测试没有启动厂商 Agent，队列接收不代表消费。投递后驱动崩溃时消息可能留在 Runtime 队列，同一目标和正文的已入队重试可返回原记录，即使驱动已离线；不同内容或目标复用该键会拒绝。确认丢失导致的两条路径重复、断线恢复和旧队列迁移仍待验证。

## Antigravity 特有路径与边界

[ACP adapter](../../../../Sources/PharosRuntime/Adapters/Agy/AgyBackendAdapter.swift) 包含以 `session/prompt` 投递 Thread 文本的方法；桌面 Thread 实际走 Mesh，不能据此认定从 room 到现有 Antigravity 会话再到 room 的回复已接通。独立 ACP Session 的 `session/update` 和权限请求用于 Session 视图；目前没有证据表明这些事件已被映射为 Thread 的实时成员状态。已有源码和本机 Session 测试不证明真实 Thread 投递、阻塞状态、多个客户端或远程 Agent 可用。远程 ACP 列表认证问题见 [Session 记录](../sessions/2026-11-07_protocol.md)。

## ACP 回合与 Thread 回复关联层（2026-11-07）

## 成员离开与重新加入（2026-11-07）
